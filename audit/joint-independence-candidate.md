# Joint block independence candidate

`lean/JointIndependenceCandidate.lean` is a **not compiled, not kernel-checked** candidate on main `f4fabf0`. It retains actual literal `Fin 4705` cell positions, actual `height`, actual suffix multiplicity, actual Q-rough support, actual smooth vertices and actual `SmoothRenewal.Edge`. It proposes reducing the joint allocation and demand premises of `literal_hcover` to a single finite-graph certificate: for each q in support and each independent subset B of the actual graph, `|B| + Σᵢ height(i)*mult(N,i,q) ≤ |vertices(Q,N/q)|`. The local demanded quantity is the entire occurrence sum, not individual cell bounds. The proof attempts to obtain `Demand` by taking the complement of a cover, then invokes `literal_hcover` with exactly that joint quantity; its allocation inequality is reflexivity. There is no allocation assumption or cross-cell deduplication.

The converse candidate shows the independence condition is **equivalent** to demand for this exact quantity. It is therefore an exact graph-theoretic reformulation, not a new proof that archive blocks satisfy the condition; a verifier/certificate for the actual independence bounds at every required block is missing. Enumeration is finite for each fixed N but potentially intractable, and checking one N does not prove all N. The literal matching and imports are themselves candidates, with separate source-data, factorization, compilation and axiom obligations. No unconditional hcover or endpoint is claimed. A disjoint-vertex packing of independently verified local graph demands can establish this joint condition, but summing overlapping local demands cannot.

`audit/test_joint_independence_candidate.py` independently enumerates small actual smooth-triple graphs and the exported ledger arithmetic. At N=6, q=1, it computes the full 20-level joint value 1, vertices {1,...,6}, independence number 5 and cover number 1; this tests a satisfiable positive case. It also verifies two actual edges {2,3,6} and {5,6,30} each separately require one deletion but their union has a common one-vertex cover {6}: summing their separate demands would incorrectly give 2. This is a concrete counterexample to naive addition, not a counterexample to the archive's true joint bound. Empty and excessive-demand cases are also tested. The tests use Python and exported JSON, not a Lean proof of the graph or JSON-to-literal correspondence.

`lean/JointIndependenceCandidateTests.lean` proposes positive edge and generic boundary examples; it too is uncompiled. No Lean build or remote run was attempted under the no-heavy-Lean/no-remote constraint. Required follow-up is an exact pinned hosted build including imports, tests and allowed-axiom gates, plus a sound practical graph certificate and archive/data provenance.
