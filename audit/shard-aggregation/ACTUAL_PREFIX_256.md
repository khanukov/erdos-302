# Actual mixed prefix 0–255: uncompiled candidate

This extends the transcribed literal prefix through node 255: 256 actual nodes,
16 independent checker modules of 16 closed declarations each, a shared literal
node function, and an aggregate checked-prefix and semantic-bound theorem.
The real references and complete node expressions come from the archive exporter;
the only default is outside the represented range. There are no additional
checker hypotheses in the generated aggregate. The archive-to-Lean match is
checked in Python, not proved in Lean. This is not the complete 1091-node bank
or an end-to-end proof of the final result.

Run `python3 -B independent_bank/prefix256_shards.py --check` and
`python3 -B -m unittest discover -s independent_bank -p test_prefix256_shards.py`.
The latter checks all generated bytes, node inventory, earlier references,
coverage, theorem shapes and mutation rejection. Both tests use the existing
hash-pinned archive loader and exporter. The generated Lean candidate **has not
been compiled or axiom-gated**. Historical CI 41439999027 at 5c4ab3b checked
the earlier 32-node prefix only, not these new declarations.

The dispatch-only `actual-prefix256.yml` rebuilds the earlier dependencies and
32-node target, then each new module sequentially with one Lean worker and a
15-minute process deadline; it gates all 256 checker declarations and both
aggregate declarations. The job has a 360-minute overall deadline. A pinned
mathlib cache may be reused, and its download or the upstream build can fail.
There is no claim that the candidate will compile within these budgets. The 18
new modules have a combined maximum of 270 minutes from their individual
15-minute caps, not a measured runtime; setup, prior checks and the global
360-minute deadline may cut that short. Actual runtime and peak memory are
unknown until hosted CI measures them. These limits do not impose a job-wide
memory cap. Failure, timeout, or missing aggregate/axiom gates is not proof.
