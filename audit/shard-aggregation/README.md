# Mixed-prefix shard aggregation: diagnostic candidate

`ShardAggregation.lean` defines a segment as the actual proposition at every index in the half-open interval. `Chain.empty 0` and repeated `Chain.append` prove a contiguous chain of such segments; `prefix_sound` yields every proposition below the final boundary. There is no assumption that any predecessor or earlier prefix has been checked. Empty or backwards segments do not permit skipping a genuine hole: `chain_sound` proves the union claim without assuming monotonic boundaries. `MixedPrefixShards.lean` specializes this to `MixedDag.Check MixedCaseTrimCandidate.extraCheck nodes`, then applies the mixed-DAG semantic soundness theorem. Its `shards` argument is still an explicit, unproved premise: it is not an unconditional bank theorem.

The core and positive/negative toy tests compiled locally with Lean 4.33.0-rc1; `chain_sound` and `prefix_sound` reported only propext, Classical.choice, Quot.sound. The specialized bridge is an uncompiled CI candidate. The extended existing manual workflow compiles the diagnostic after its existing mixed modules, and gates the new declarations' axioms; it has not been dispatched. No archive-derived shard is generated or proved here.

## Exact remaining construction

* Reify one shared `nodes : Nat → MixedDag.Node Payload` from the exact immutable hashed archive bytes. For small nodes preserve the literal normalized support and demand; for case nodes preserve occurrence order, strictly earlier scaled refs and the full reachable tree, translating dual row indices to actual constraints and preserving signed weights/residuals and both split branches; for trim nodes derive the literal normalized active support and reference scaling; for qpack retain all 7 row occurrences, scaled refs, common-denominator weights and normalized target. Reject unsupported tree forms, bad indices, non-integrality, wrong normalization, absent/duplicate nodes and malformed numeric/Boolean values. Exact byte-to-Lean correspondence remains an external code-generation trust boundary unless separately formalized.
* For each explicit interval `[a,b)`, prove `Segment (MixedDag.Check extraCheck nodes) a b` by kernel reduction of **every actual check**; the proofs must reference the very same generated `nodes` and checker, with no dummy predecessors. Compile shards independently against the same dependency/source/toolchain snapshots. Start with a small shard, then individually test the large case nodes, trims and pack. `small` evaluates every subset of its support and cover relation, not merely the archive's claimed answer. Cases check reference scaling/subsets plus the entire case tree, and trims check image edges; qpack checks all occurrence capacities and weights, not assumed source bounds.
* Have an assembly module import the complete shard inventory and construct a chain from 0 to 1091; the kernel verifies no gap and identical predicates. Apply `MixedPrefixShards.sound`, print its exact 1091-node theorem type and gate all load-bearing axioms. CI must reject missing/duplicate/unexpected artifacts, bind producer run and source SHA, validate dependencies and explicitly disclose imported `.olean` reuse. Compilation of all shards alone is not a successful assembly. Link these certified bounds to actual downstream profiles/ledger and archive correspondence separately; a prefix bound is not the Erdős endpoint.

## Measured work, not a runtime prediction

The Python exporter on the pinned archive reports 1080 small nodes, 7 case nodes, 3 trims, 1 pack. Small support-size distribution: 3:399, 5:50, 6:231, 7:32, 8:146, 9:222. The sum of `2^|U|` is 174712, max per small node 512; a deliberately loose structural proxy `sum 2^|U| |U|^3` is 106882024 (max 373248). It is not a count of Lean kernel steps: reductions, short circuiting, finite-set representations, proof terms, sharing, and elaboration can dominate or change the cost. Case supports have sizes 15,17,21,32,40,42,46 and 3,4,6,27,100,105,116 reference occurrences; 23 visited dual leaves were identified by the prior Python diagnostic. Pack node 1090 has 7 rows, support size 21 and normalizer 1. No elapsed-time/memory extrapolation or feasibility conclusion is justified until representative actual kernel shards are measured, particularly the largest case trees. The exporter is corroboration only, not a kernel proof.
