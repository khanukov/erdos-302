# Occurrence-aware renewal candidate

Status: **uncompiled Lean candidate, not a kernel-checked theorem or an unconditional endpoint**. No remote, main-branch modification, heavy Lean build or hosted CI was attempted. The local worktree has no Mathlib checkout. The Python reference tests are executable sanity checks only.

`RenewalMultiplicityCandidate.expansion` is an arbitrary finite-level nested power-occurrence sum (in particular 20 levels). It retains repeated power choices; the candidate theorem derives it from the recurrence rather than assuming a global inequality. This is not yet the unique suffix-smooth-factor formulation: equivalence requires a distinct-prime factorization/reindexing proof. The required correction identity against actual ledger cell occurrences and the certificate of demand for every smooth prefix remain open.

`occurrence_cover` and `occurrence_hcover` formulate the desired local-to-global step using a natural multiplicity for each cell and rough block. The per-cell equality `count i = ∑ q, mult i q` must be established against the literal analytic cell count, including the rough-factor bijection and quotient endpoints. The pointwise allocation inequality must be derived from the recurrence expansion and cell correction identities; it is not a global weighted-cover assumption, but it is still an explicit unproved hypothesis. The graph demand, roughness, triple-freeness and boundedness are also explicit. `occurrence_hcover` gives the abstract weighted-count form; specialization to the literal ledger is not provided.

The Lean test candidates include a repeated-divisor example, empty levels, and the 20-level zero boundary. They are not compiled. Run the independent reference checks with `python -m unittest discover -s tests -p test_renewal_occurrences.py -v`. Their passing does not verify Lean proofs, archive provenance, graph certificates, or the endpoint.
