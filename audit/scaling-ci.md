## Exact schema and relation to the theorem

The publication zip contains `erdos302_boundary_certificates/baseline/bank.json.xz`, schema `erdos302-standalone-finite-proof-bank-v1`. There are 4,106 nodes and 25,744 image table entries. Python inspection of that table found **every one has d=1**; rational d>1 is supported by the independent interpreter's general format, but not needed by the image entries of this particular baseline. This observation is not a Lean-checked assertion about archive bytes.

`independent_bank/bank_interpreter.py`, lines 22–28: an image identifier j indexes `images[j] = [i,m,d]`; i is the **source node index**, not the image index; i must precede the consumer node index. Both m and d are positive, coprime integers; for every vertex v of the already normalized source support, `d ∣ v*m`; image vertices are `(v*m)/d` and the source demand is retained. `pack` and `qpack` rows refer to image IDs in their first column, `case.cs` lists image IDs, and `trim.ref` is an image ID. The result of every node is sorted then normalized by dividing each vertex by the gcd of the full support, preserving demand. Its soundness is another application of `bound_image` with m=1 and d equal to that gcd; the implementation still needs to prove gcd positivity and divisibility.

`ArchiveScaling.image` is the Finset image of exactly `(v*m)/d`; `Bound` has the same unfolded definitions as `Extended.Bound` / `UpperBridge.OrderedCover` and `OrderedEdge`. The candidate adapter demonstrates intended definitional conversion. The theorem assumes exact divisibility on the *whole source support*, and proves strict order and injectivity there, the polynomial edge equation in both directions, image-edge reflection including preimages, and lower-bound transport via a filtered finite pullback and an injective cardinality comparison. Coprimality is unnecessary for mathematical soundness and is intentionally not a premise; it remains an archive-format check. Index bounds, positivity checks, support construction, gcd normalization and translation of the archive into Lean data are outside this lemma.

Concrete archive example: image ID 2 is `[0,4,1]`; node 0 is the small node `[2,3,6]` with r=1; case node 4 refers to image ID 2 in `cs`. The image is `[8,12,24]`. `ScalingTest.lean` proves this example and also attempts both a reduced synthetic 3/2 example on `[4,6,12]` and a non-coprime 2/2 example; a nonintegral product is rejected by the exactness premise. These test facts do not verify archive serialization or all entries.
