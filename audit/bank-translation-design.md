## Soundness boundary and exact relation

1. Pin the authoritative ZIP externally, verify its digest before extracting, reject duplicate archive members and JSON keys, validate exact schema and types, and validate every row, including unreachable or unused rows. Check decompression limits and fail closed; never allow Python bool as integer. Disallow unknown variants/fields, dangling/non-earlier references, invalid scales, and malformed/nonpositive weights. Make artifact generation deterministic. The digest is an operational provenance check, not a Lean theorem that ZIP bytes denote a particular mathematical object.
2. Eliminate trust in the translator by representing the bank's complete typed input as Lean data, and defining a Lean-side translation/replay relation or checker over that data. Prove that the generated DAG exactly agrees with the result of the Lean translation on **all** nodes, images, supports, demands, rules, references and weights, and that all input rows are consumed or explicitly accounted for. The theorem must mention that exact bank object and desired target, not merely existentially quantify arbitrary data or trust a Python assertion. A Lean parser for pinned uncompressed bytes plus a verified digest/parser is the strongest self-contained byte-to-object route; otherwise state honestly that archive-to-Lean-data transcription and byte identity are external reproducibility assumptions, checked independently in CI. Reproducible generation and matching hashes alone are not a kernel proof of archive correspondence.
3. Existing `ArchiveDag.sound` checks arbitrary nodes but does not establish archive identity; its `Check` accepts weaker demands. A generic `sound` application alone cannot establish exact archive translation. Require exact equality of interpreted demand/support to the bank's canonical values at every mapped node, not merely `≤`, and explicit index mapping. Never emit `axiom`, `sorry`, `admit`, or arbitrary generated proof assertions. Generated terms may provide only data and certificates whose predicates are kernel-checked using proved soundness lemmas. Avoid `native_decide` if the desired trust boundary excludes native compiler/FFI; use kernel reduction/decide or document any extra trust.
4. The interpreter normalizes **every node** by dividing support by its gcd, and resolves images by scaling an earlier normalized node, with positive coprime numerator/denominator and exact divisibility. Translate each referenced image to a checked image DAG node, then normalize the consumer via an additional checked image scaling by `1/gcd` (when needed). Check support equality as finite sets, demand equality, gcd positivity, integrality, multiplicity and index mapping. The same image may occur in multiple consuming rows; materialize it only after its source exists and before its first consumer, or separately per consumer, preserving strict ordering. A single global image-prefix violates DAG ordering. Distinct image indices may denote identical supports: do not collapse them without summing their weights and proving the transformation.
5. `pack`: replay each listed image, preserve row multiplicity and positive integer weights and D; verify load per vertex, objective and ceiling via exact integer arithmetic. `qpack`: choose LCM of denominators, use integer weights `numerator*(LCM/denominator)` and D=LCM; prove equivalence, guard size blowup. The archive's single qpack happens to need only D=1; do not silently generalize that observation. Maintain all required image/source checks and prove exact post-normalization support.
6. `trim`: add a proved rule: removing vertices in no ordered edge preserves every covering constraint and thus the bound on the active-edge support. The current DAG has no trim rule. Exhaustive search on arbitrary input supports is not a general substitute: cases reach 902 and packs 7,495 vertices.
7. `case`: add a verified finite branch-tree certificate checker and soundness theorem over a cover restricted to target support. For each constraint image U,r, derive the restricted lower bound `r - |U \ T|` using integer arithmetic or a justified truncated subtraction; prove the distinction is harmless where used. Replay `dual`, `split`, and `force` against path-specific ones/zeros and residual demands; check tree edges decrease, every node reachable if reproducing archive acceptance, split vertices are free, and exact integer capacity/objective inequalities. Do not import the Python validator's truth value as a theorem. Enforce all case constraint references are prior even if unused. Reject `budget` and `row` until their checked semantics and proof are implemented, despite current interpreter supporting them; subsequently add both with tests if full format compatibility is wanted.
8. `externalActive` cannot be generated as a fact. A conditional soundness theorem must take four explicit hypotheses `Extended.Bound` on the **exact** active supports and demands, with provenance spelled out; alternatively prove those bounds from independently verified upstream data. The profile number computed from intervals alone is not a proof of the needed covering bound. A conditional theorem cannot be reported as unconditional.
9. To prevent accidental partial success, production full-bank mode must reject unsupported variants (currently `case`, `trim`, external leaves, and qpack absent a translation); emit no purported complete artifact on rejection. Optional subset mode must print excluded node IDs and dependency closure, label its theorem partial and conditional as appropriate, and never silently discard nodes or roots. Ensure failure is nonzero and output replacement atomic.

## CI implementation and tests (not executed here)

Implement in vertical slices with explicit RED/GREEN tests: typed parser and strict rejection; source/image expansion; small nodes; pack; qpack; trim; case; explicit external assumptions. Test synthetic tiny banks against an independently written brute-force finite cover oracle, not only the translator or archive interpreter. Include duplicate keys/members, booleans, unknown tags/fields, bad ordering, invalid image indices/scales/nonintegrality, normalization, duplicate images and supports, malformed rational denominators, zero/nonpositive weights, integer overflow/oversized resources, overload, wrong ceiling, mismatched support/demand, unreachable case nodes, invalid force/split/dual/path, and external assumption mutation. Mutate every behavior-bearing input field and assert rejection or changed verified artifact. Include canonical archive census and full per-node correspondence checks against an independent interpreter as regression evidence, not as a substitute for Lean soundness. Run `lake build` and audit generated theorems' axioms on CI only; no local Lean was run. Add batch/chunk sizing and time/memory measurements: 623,846 row occurrences and max 6,339 refs make naive giant Finsets, repeated definitions or monolithic kernel reduction high risk. Publish observed limits; do not claim CI readiness before exercising the full archive in CI.

## Blockers

Existing `lean/Dag.lean` has only edge, small, image and pack; no proved case/trim rules or explicit external assumption constructor. No formal archive-to-Lean-object relation exists. The four external covering bounds are unproved. There is no established target mapping because archived roots are empty. A full translator cannot honestly be called CI-ready without these proofs, full-bank kernel-checking and resource measurements. This report intentionally does not create an unverified translator or claim the earlier generic DAG CI proves this bank.
