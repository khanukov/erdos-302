# Full-bank local-view sharding: candidate and remaining proof obligations

Historical design note; see `FULL_LOCAL_ASSEMBLY_STATUS.md` for the newer candidate bridge and current scope.

Source: `eedfb2a`. This is **not a checked Lean proof**. The generator produces data modules only; the existing Python interpreter and roundtrip checks are corroboration, not a kernel theorem about the archive.

## Concrete generation and measurements

Run `python independent_bank/full_local_shards.py EMPTY_OUTPUT_DIR --target-bytes 262144`. It authenticates and parses the pinned archive with the existing loader, validates/interprets it, transcribes the existing complete producer, checks strictly backward dependencies, and partitions **consecutive archive indices**. Actual run: 4,106 nodes, 623,846 reference occurrences, 123 modules, 34,911,177 total module bytes; largest module 1,200,315 bytes, for node 4101 alone. The target bounds the sum of actual-rule source bytes within a shard, **not** the module size: predecessor snapshots and an indivisible rule can exceed it. 262,144 is not a memory bound. No Lean memory measurement or compile is claimed.

Counts: small 3,528; trim 3; pack 448; qpack 1; case 122; externalActive 4. Every module stores actual rules for its interval, and support/demand snapshots for outside predecessors; snapshot rules are intentionally `.small` and must never be treated as verified source rules. Dummy defaults apply elsewhere. Thus the modules are independent data inputs, not full-bank replays.

`test_full_local_shards.py` compares every real arm and every required predecessor snapshot with the full transcription, checks exact interval coverage and source ordering, and rejects forward/self and Boolean source mutations. Existing full-export, archive taxonomy and full roundtrip tests also passed. This tests Python transcription and generation, not Lean reduction or semantic soundness. File equality with the existing producer is not an independent proof of archive correspondence.

## External assumptions

Nodes 1097, 1107, 1112, 1114 are externalActive. Their literal support/demand `Extended.Bound` propositions remain explicit hypotheses. `extraCheck` for an external node includes that bound; no `decide` can discharge it. No blanket `fullTarget` hypothesis should be counted as verification. Nonexternal ordinary case and trim rules require the existing soundness contract; signed residual case rows, both split branches, duplicates and qpack rational-weight normalization must survive unchanged. `MixedDag` also has edge/image rules even though the archived full export here uses neither; a general lemma must handle them or explicitly limit its theorem to this actual bank.

## Path to a real checker

1. Prove a one-node semantic lemma: `Check extraCheck ns i` plus prior source bounds implies the bound at `i`, without requiring checks at unrelated earlier nodes. Factor the existing `MixedDag.sound` branches or prove a suitable generalized induction helper; establish the external payload contract from the **four explicit bound assumptions** and ordinary payload contract from `MixedCaseTrimCandidate.extra_sound`.
2. Prove a checker-locality lemma: local and global views agreeing on the current entire node and on support/demand of every reference occurrence imply equivalent checks. It must cover `.small`, `.pack`, `.extra` trim/case and the signed trees; handle edge/image for a genuinely generic lemma. Duplicate references are occurrences, not unique edges. Case `row`/`image` depend on source support/demand; trim checks ordered edges and both depend on scaling. Ensure all required source indices are strictly earlier. Prove and test this statement, rather than assuming that Python's snapshots imply Lean equality.
3. Generate per-node/shard `Check` proofs for all nonexternal nodes and conditional proofs for external nodes. Exercise finite representative shards including all six types, node 4101 (the largest indivisible rule), outside-support negative residuals, duplicate references, and negative mutations. Budget cases by measured kernel time/peak RSS; per-source bytes do not predict elaboration memory. Large single case trees may require a separate tree-node representation and proved equivalence before its module can shrink further.
4. Establish a small canonical support/demand ledger for all 4,106 archive positions and prove each local view agrees on its interval and all of its predecessor snapshots. Local rules are not globally faithful outside each interval. Design a hierarchical interval soundness assembly in strict archive order using the one-node lemma; each shard consumes only already-proved semantic bounds and produces its own. Avoid importing a 30 MB monolithic rule definition; measure actual imported `.olean` environment/peak RSS, since merely splitting source files does not guarantee bounded assembly memory. If a final aggregator necessarily imports all shards, report its real memory and devise a compositional certificate/streaming kernel-checked assembly if necessary.
5. Require exact manifest inventory, shard hashes, index coverage and complete dependency checks; independently regenerate and compare **all** data and surrounding declarations byte-for-byte. Bind archived producer artifacts to exact pinned source/toolchain/run, axiom-gate each shard and the aggregate, and verify all four assumptions remain visible in theorem types. Run a bounded representative hosted Lean build before scaling. No hosted build was run here.

The current generator itself initially renders the full 30 MB string in Python to reuse the audited translation, so it reduces candidate Lean module size, not generator memory. For a fully streaming producer, refactor the translator to render one verified node at a time while retaining exact-byte regression against the existing producer. The Lean-to-archive relation remains an external provenance claim unless separately formalized.
