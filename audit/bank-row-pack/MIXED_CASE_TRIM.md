# Mixed case/trim extension: CI candidate

This is an **uncompiled candidate**, not a verified Lean result. `MixedCaseTrimCandidate` instantiates `MixedDag.extraCheck` with finite case and trim rules and supplies `extra_sound` from the prior-node bounds delivered by `MixedDag.sound`; `sound` has only the check of the ordered DAG as a premise. Case checks every strictly earlier scaled reference, divisibility and inclusion of its image in the target, then runs the recursive case tree. Trim checks a strictly earlier scaled reference, target inclusion, retention of every edge in the image, and the demand inequality. No semantic bound or archive-correspondence proposition is included in the executable rule. The branch/dual tree retains row occurrences and signed integer residuals.

The case rule is intentionally restricted to images contained in the target. Outside-target images and their corrected signed residuals are unsupported. This says nothing about the validity of other archive cases. Case/trim support in this generic checker is not archive transcription: no generated archive instances, translation equivalence, or full bank replay are claimed. The seven prefix cases (361 reference occurrences) and three trims are Python-only applicability diagnostics; see `independent_bank/CASE_TRIM_PREFIX.md`. That diagnostic uses assertions and is intentionally run without Python `-O`.

The checked-in test candidate includes positive-demand synthetic case and trim DAGs whose predecessor checks are part of the same `MixedDag.sound` derivation, a bad self-reference and a trim that deletes an edge vertex. These are intended instance validations, **not yet kernel-validated**. CI checks the tests and named theorem axiom reports; a successful future run covers only that exact commit and scope. It is not a claim about archive bytes corresponding to Lean data.
