# Data-only comparison of upstream and reported profiles

`python3 -I -S -B audit/profile-only-gap.py` reads only JSON members of the SHA-256-pinned publication ZIP, from the same bytes whose digest it checks; it never imports, extracts or executes archive code. `python3 -I -S -B -O` produces the same results. Checks are explicit exceptions, not Python assertions. `python3 -B -m unittest audit.test_profile_only_gap -v` exercises optimized execution with independently repinned malicious fixtures; repinning is solely for testing checks beyond the hash gate.

The precise comparison is **the old pinned upstream interval profile**, not the archive report's stronger preceding profile-only baseline. In the common prime order p_j, let rho_j = product over i<j of (p_i-1)/p_i. A correction of height h on [a,b) contributes h(1/a-1/b) to J_j. Repeated renewal and the smooth/rough block decomposition yield the coefficient C = 1 - sum_j rho_j J_j, provided the correction profile is a valid cover lower bound and the global counting argument applies. The script applies this identical functional to the old intervals (counting overlaps with multiplicity) and to the reported weighted new cells, with exact rationals; it checks the old value against the upstream CK and the new value against both report and claim. Thus the two calculated coefficients are comparable **for these two profile datasets under the same counting construction**, conditional on their semantic premises. The old coefficient is approximately 0.8461739827964 and the new one approximately 0.84123080705. Their exact difference is printed by the script.

The archive itself reports a different, stronger *preceding profile-only bound* of approximately 0.841263594506. This calculation does not reconstruct or compare with that baseline and must not be presented as the archive's exact improvement over it. Neither the coefficient inequality nor agreement with CK establishes that the upstream interval transcription equals the theorem at every level; the archive's upstream theorem is an external premise. The new cells are taken from a report, not independently derived from valid bank/extension certificates. The computation is not a Lean proof or an unconditional validation of either bound, nor proof of a global improvement over every earlier result.

The recurrence is evaluated for each level and n=1..10000, scanning levels first, n second. The first strict increase in that bounded scan is level 14 (prime 43), n=1984, 217 to 218. This is a difference between reconstructed numerical profiles, not a proof that all new values dominate all old values. A separate test uses direct interval membership rather than difference arrays, through n=1984; it independently reproduces the displayed tuple within that smaller scan. The coefficient calculation uses all reported cells through cutoff 500000, not just the n<=10000 scan. Neither finite scan validates the cells' mathematical derivation.
