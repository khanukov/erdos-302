# Fast small-node proof extraction: partial, no new verified nodes

Classification against the SHA-256-matched original 1,900-node manifest is reproducible with `python3 classify.py`. Of the 1,628 unverified nodes: r=1, |U|=3: 886; r=2, |U|=5: 60 and |U|=6: 282; r=3, |U|=7: 32, |U|=8: 146, |U|=9: 222. The source is parsed as data only.

`generator.py` generates direct-edge proofs for r=1 with the exact bank source index and vertex set. It can resume non-overwriting batches, and records each exact index, source hash, axiom query, termination reason and exit status in coverage.json. It checks the original source hash and counts only fully successful batches. Limits are wall time, process-group aggregate RSS (3.5 GiB) and 3 GiB disk floor. Example: `python3 generator.py --seconds 120 --timeout 60 --batch 1 --max-nodes 1`. Failures stop a run; failed entries remain recorded. There is no `sorry` or `native_decide` in generated proofs. The r>=2 case is not implemented.

**Results:** three individual real-node attempts (2756 twice, 4022 once) failed by the explicit 3.5-GiB process-group RSS limit; none were Lean-verified. Import-only test also exceeded 50 seconds under concurrent heavy Lean activity. No axiom output was produced for the new declarations. Prior verified count remains 1,900; remaining 1,628. The manifest, Lean source and failure logs document the attempts; a successful Lean exit and each node's axiom query are mandatory before counting.

**Proposed r>=2 method, not yet formalized:** enumerate only (r−1)-subsets of U and prove each misses a valid edge; every smaller subset extends to an (r−1)-subset because |U|≥r−1, so no smaller cover exists. Alternatively use r pairwise disjoint valid edges where available. Check validity by kernel proofs and ensure all reductions use small edge supports; do not use full powerset or assume Python search is a proof. Since import-only was not demonstrably cheap in this environment, diagnose import memory and coordinate concurrent Lean jobs before running further batches.
