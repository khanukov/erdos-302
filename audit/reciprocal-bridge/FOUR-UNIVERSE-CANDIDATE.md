# Four-universe closed-bound candidate (not Lean-verified)

This is a **candidate**, not a proof result. No Lean build of these declarations has run. The candidate builds on `6fc5742`; its four literal universes and 44 edge shards are unchanged. `FourUniverseCandidate.lean` attempts to prove each `U n = universe_i` by replacing upstream `PrimeSupported` with a decidable bounded predicate: a prime divisor of positive `x` is at most `x`. It partitions each `1..n` into 32-element intervals, proves finite membership in each interval by kernel reduction, proves the literal's range, and combines the results by extensionality. The four `closed_bound_*` candidates apply the pre-existing conditional edge-retention assembly to those equalities. The exact types and axiom reports must be checked in a successful run; kernel evaluation, elaboration, resource sufficiency, and the assembly itself are all unverified.

`.github/workflows/four-universe-candidate.yml` is dispatch-only. It rebuilds the 235-module pinned upstream reflective source closure in the same job, applies the documented byte-gated compatibility transformations, builds the literal edge shards, soundness, assembly and universe modules, and gates 44 shard and 22 bridge/endpoint declarations. It pins Lean binary hash, upstream revision, Mathlib revision, manifest dependencies and GitHub Actions, while reusing Mathlib cache objects. The job's 355-minute deadline and per-process 24 GiB virtual address-space cap are not an aggregate memory cap. See `FOUR-CI-INVENTORY.md` for upstream compatibility transformations and underlying trust boundary. A prior success on another SHA does not verify this candidate. The 44 unchanged edge checks are now separate modules importing shared universe definitions, with an import-only aggregator. The single job builds them serially in fresh Lean processes, reusing upstream objects produced earlier in that same job; it may exceed the deadline or memory cap. The split has not yet been Lean-verified and does not guarantee resource sufficiency.

Local tests verify generator reproducibility, complete nonoverlapping partitions, and independently recomputed finite prime-support membership; existing edge tests check retention and mutation sensitivity. Those Python checks are not Lean proofs. The candidate does not establish archive-bytes-to-Lean correspondence, full mixed bank/profile replay, or the final asymptotic theorem, even if the four closed-bound declarations compile.
